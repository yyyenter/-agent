# 2026-04-20 工作日志

## 架构升级：从单 Crew 到 Flow 多 Crew 模式

用户自主将项目从单一 `@CrewBase` 模式升级到 CrewAI Flow 模式，引入四个独立 Crew：
- `RouterCrew`：提取用户消息中的地点/主题/食物
- `WeatherCrew`：查询实时天气
- `ResearchCrew`：调研美食/景点
- `ReportingCrew`：汇总生成报告

Flow 节点：`route_user_request` → `handle_weather` + `handle_research`（并行）→ `generate_final_report`

## 修复：route_user_request 方法失败

根本原因：所有 4 个 `@CrewBase` 类共用同一套 `config/agents.yaml` + `config/tasks.yaml`，导致 YAML key 查找混乱。

解决方案：为每个 Crew 单独建 YAML 文件：
- `router_agents.yaml` + `router_tasks.yaml`
- `weather_agents.yaml` + `weather_tasks.yaml`
- `research_agents.yaml` + `research_tasks.yaml`
- `reporting_agents.yaml` + `reporting_tasks.yaml`

每个 `@CrewBase` 类内显式声明 `agents_config` 和 `tasks_config` 路径。同时清理了未使用的 `TravelReport` 模型和多余 import。

## 记忆系统开启

4 个子 Crew 全部开启三种记忆：在每个 `@crew` 方法的 `Crew()` 构造里加 `memory=True`、`entity_memory=True`、`long_term_memory=RAGStorage()`，并 import `RAGStorage from crewai.memory.storage`。
